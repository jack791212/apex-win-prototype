## 2. ⭐ 那條號稱在守這件事的鎖，自己有一個會把五款桌遊靜默弄壞的洞

`platform/lazy-css-rides-with-game` 的 (c) 判斷「這個前綴是不是該款獨有」時，
判準是「**該前綴在其他 `src/views/` 檔一次都沒出現過**」。

而 `.ax-tbl__` 是 `core/table.js` 畫出來的。`views/table-roulette.js` 裡**剛好**有一個 `.ax-tbl__stake`
⇒ 在 views-only 的量程下，`ax-tbl` 被判成「輪盤獨有」。

**跟著這條鎖走會發生什麼**：它會**要求**把 `.ax-tbl__*`（1,581 bytes）搬進輪盤的私有樣式檔。
於是百家樂／龍虎／骰寶／幸運轉盤／安達巴哈**五款當場沒有籌碼列與下注面板**，
而 `node prototype/tests/run.js` **全綠**。

這與 `platform/rg-bet-gate-coverage` 2026-09-02 修過的是**同一種病**：

> **尺的量程漏了一段，而「防空心」的保險也架在同一段量程裡。**
> `exclusiveChecked >= 1` 數的是「量程內」的前綴數 —— 量程漏掉整個 `core/` 時，那個讀數完全正常。

**修法**：(c) 改掃全 `src/`，並加兩條反向不變量：

- **(c2)** 這把尺**必須**量得到 `views/` 以外的檔（縮回 views/ 就轉紅）。
- **(c3)** 掃描端**必須**剝註解 —— `core/ui.js` 有一行註解提到 `ax-dice__card`；
  不剝的話 `ax-dice` 會被判成「共用」⇒ (c) 就**不再檢查它**＝fail-open，而且全綠。

### 2.1 而 (c3) 的第一版，自己就是空的

第一版 (c3) 寫成「拿一個合成字串去打 `stripComments` 自己」：

```js
t.ok(stripComments("/* 同 .ax-probe__card 一樣 */\nvar x = 1;").indexOf("ax-probe__") < 0, ...)
```

那只證明**這個函式會剝註解**，**沒有證明掃描端用了它**。
把掃描端的 `stripComments(...)` 拿掉 ⇒ **照樣全綠**（負向擾動 **P6 實測 MISSED**）。

改用**活見證者**：至少要有一個前綴「只有把註解算進去才會被誤判成共用」（現況＝`ax-dice`），
而它現在必須確實落在受檢清單裡。掃描端一旦不剝註解，它就掉出清單而轉紅。→ 12/12 CAUGHT。

> ⇒ CLAUDE.md §4 形狀⑦ 的再一個變體：**反空綠的錨，本身也可能只認寫法不認概念。**

## 3. ⭐ CSS 的勝負關係會被「搬家」翻轉，而那不改任何一個字元

延遲樣式檔是在 `components.css` **之後**載入的。CSS 同特異度時「**後寫者勝**」
⇒ 一條規則只要從 `components.css` 搬進 `game-*.css`，它與**同特異度留守規則**的勝負就翻面。

遷移宣稱「規則一條未改、只搬位置」，而這一類改變**一個字元都不用改就發生**。

**實際踩到一次**：

```
舊 components.css:159   .ax-pump__go     { background: …; color: #1a1206; }
舊 components.css:464   .ax-btn-primary  { …; background: var(--ax-grad-gold); color: #2a1b00; }
```

按鈕標記恆為 `class="ax-btn-primary ax-pump__go"`（兩個 class 必定同時存在），兩者同為 (0,1,0)
⇒ 舊世界由**後寫的** `.ax-btn-primary` 勝 ⇒ **`.ax-pump__go` 的那兩條宣告從來沒有生效過（死碼）**。
搬進後載入的 `game-pump.css` 後它們**反過來贏**，文字色 `rgb(42,27,0)` → `rgb(26,18,6)`。

**處置＝保住原本的渲染結果（零視覺改變），直接刪掉那條死規則並在原處寫明理由。**
理由：遷移的契約是「只搬位置」；在一次純搬遷的提交裡順手改變視覺，
正是本專案最怕的那種「看起來沒事」的改動。

**新鎖 `games/lazy-css-no-cascade-flip`**：同一元素上「搬走的單 class 規則」與「留守的單 class 規則」
不得宣告同一屬性（含簡寫／長寫，如 `background` vs `background-color`）。
同元素的判準＝view 裡的 class 字串字面量（`class: "a b"`）——node 端唯一可靠的「哪些 class 會落在同一個元素上」。

### 3.1 修好之後，這條鎖全庫已無見證者

唯一那組對撞被刪掉了 ⇒ **真實資料再也餵不出紅燈**，這條會變成「永遠不會紅」的空綠規則
（同 2026-09-14 維護軌 R13 的 P12）。
⇒ (c) 直接拿**合成輸入**打純函式 `findFlips`，逐字重現 pump 那一組。

## 4. 驗證方式（本輪的方法本身值得留）

用 §9 的線上路徑做**遷移前／後對照**：

1. **遷移前**，對**線上舊版**逐元素抓 41 個 computed style 的指紋（25 款遊戲，走 `HL.router.goGame()` 的真實玩家路徑）。
2. **連抓兩輪取交集** —— 剔除「本來每次進場就不同」的元素（`cases` 的隨機箱內容、`picks` 的隨機隊名換行）。
   沒有這一步，`picks` 會報 8 個假差異（全是 `height`，因隊名換行行數不同）。
3. 指紋存進 **`localStorage`**（活得過 reload，而 SW/caches 清除不影響它）。
4. push、等 Pages、**逐支檔案確認新版真的到了**才開始量。
5. 對**線上新版**同法再抓一次，逐元素比對。

**最終：比對 3,336 個元素，樣式改變 0。**

**第二條獨立路徑**：在真 DOM 裡用 `el.matches()` 掃「同特異度對撞」
（搬走的規則 × 留守的規則 × 同一元素 × 屬性重疊）。
兩條路徑**各自只抓到同一條**（pump），互為佐證。

**省下來的位元組是真的**：開機時遊戲樣式檔載入數 **0**；開一款才來一支，且**只來那一支**
（實測 `money-wheel` → `game-money-wheel.css`，再開 `pirots` → 多一支 `game-pirots.css`）。

### 4.1 射程邊界（據實）

- 指紋量的是**預設渲染狀態**。`hover`／`disabled`／`is-win` 這類**狀態樣式**不在射程內。
  （新鎖 `lazy-css-no-cascade-flip` 是靜態掃描，涵蓋得到這些狀態的規則，算是補位。）
- 「**好不好看**」仍記 **UNVERIFIED** —— 這條路徑量得到樣式**值**，量不到美感。
- `rAF`／CSS transition 的補間仍不可靠（見 [scheduled-visual-verification-2026-09-12.md](scheduled-visual-verification-2026-09-12.md)）。

## 5. 給下一個要搬樣式的人的三條

1. **先問「這個前綴真的只有這一款在用嗎」，而且要掃全 `src/`，不是只掃 `views/`。**
   共用外殼常住在 `core/`。
2. **搬家會翻轉同特異度的勝負。** 搬之前先找出「這條規則所在元素上還有哪些 class」，
   以及那些 class 的規則有沒有宣告同一個屬性。新鎖會擋，但知道為什麼比被擋住重要。
3. **驗收要用「遷移前／後對照」，不是「搬完看起來還好」。** 而且對照組要**連抓兩輪取交集**，
   否則隨機內容造成的 `height` 差異會淹掉真正的差異。
