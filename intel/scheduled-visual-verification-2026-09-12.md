## 0. 為什麼這件事重要

本軌的紀錄裡，「無 preview ⇒ 無目視」出現過至少 10 次，而它是兩件事的**共同前置**：

- **管線頂端 3 筆 `specd`** 的阻塞原因逐筆寫著「重量級 slot 建置**需可靠 preview**」，
  而本軌**自 2026-08-21（Moles）起 22 天沒有上線新遊戲**。

也就是說：這一條「做不到」的前置，同時擋著**上線新遊戲**與**宣稱過閘**兩件事。

## 1. 配方

```js
// ① 開分頁（不需要 dev server；?demo=1 讓 HL.auth.backend() 為 false ⇒ 過得了登入 gate）
preview_start { url: "https://jack791212.github.io/apex-win-prototype/prototype/?demo=1" }

// ② 走玩家真實路徑（**不是** CLAUDE.md §9 那個 h.appendChild(g.render()) 的 headless 配方——
//    那個配方刻意繞過 renderApp/mountView，凡缺陷住在「掛載／離場／換頁／同頁重繪」就一定驗不到）
await HL.lazyGames.load('<id>');
HL.router.goGame('<id>');

// ③ 量測：用 MutationObserver + setTimeout（兩者在此環境都是**真實速度**）
```

⚠️ **改完 code 要驗自己的改動，得先 push**：這條路量的是**線上部署站**＝HEAD，不是工作區。
GitHub Pages 約 1–2 分鐘生效；驗之前先 `navigator.serviceWorker.getRegistrations()` 逐一 `unregister()`
＋ `caches.keys()` 逐一 `delete()`，再用 `fetch('./src/views/<檔>.js?cb='+Date.now())` **確認新版真的到了**
（CLAUDE.md §4 已記載 PWA SW 會餵舊檔；不做這一步會驗到舊版而以為自己沒改成功，或更糟——以為改成功了）。

## 2. 射程邊界（**本輪實測**，不是推測）

| 能力 | 結論 | 實測證據 |
|---|---|---|
| JS 執行 / `HL.*` 全域 | ✅ 完整 | `HL.games.all().length` = 65；`HL.gset.get('fast')` 讀得到 |
| `setTimeout` 計時 | ✅ **未被夾** | 10ms→14ms、100ms→108ms（分頁開了 ~6 分鐘後複測仍準） |
| DOM 結構 / class / 文字 | ✅ 完整 | `MutationObserver` 逐拍收得到 |
| 節點識別（重建 vs 就地改） | ✅ 完整 | 給節點掛 `__id` 後回頭數存活數 |
| `computer{action:"screenshot"}` | ✅ **會成功** | 舊紀錄「截圖常逾時」在本環境**不成立** |
| `requestAnimationFrame` | ⚠️ **只在截圖時成串觸發** | 靜置 2.5 秒 **0 幀**；截 4 張後累計 85 幀 |
| CSS transition / animation | ⚠️ **只在截圖時推進** | 20 秒線性位移：靜置 42 秒仍**凍在 x=63/600**，只在那 4 次截圖時各跳一格（0→1→17→40→63） |

### 這張表真正的意思

**畫面不是「不會動」，而是「只在你截圖的那一刻動一格」——截圖就是影格幫浦。**

於是：
- **「節奏/時序有沒有做對」＝可驗**（JS 與計時器都是真實速度 ⇒ 拍的順序、間隔、DOM 變化全部量得到）。
- **「補間動畫長什麼樣」＝仍不可靠**（要靠連續截圖一格一格幫浦，粗糙且與真實幀率無關）。

⇒ **保真閘第 10／11 項的處置應該分成兩層**（見 §4）：
「**有沒有分階段／分級**」現在**可驗**；「**動畫本身好不好看**」仍是 `UNVERIFIED`。

## 3. 本輪立刻換到的成果：game-feel #26 從「⬜ 未做」到修掉

|---|---|---|---|
| `golden-toad` | **1** | t≈2ms 一次「15 拆／15 建」，其後 **3.6 秒零變動** | 最終盤面一次全現形 |

⭐ **正向對照是這組量測的關鍵**：如果每一款都量到「1 拍」，那證明的是**儀器壞了**而不是遊戲有缺陷。
shadow-ritual 的 6 拍證明**量具有見證者** ⇒ 那兩個「1 拍」是真的沒有分階段。
（這正是 CLAUDE.md §4 形狀⑦ 反覆講的同一件事，換到量測上：**沒有反例的量測，等於沒有量測。**）

## 5. 兩個誠實的但書

- **這條路量的是線上站（HEAD），不是工作區**。要驗自己這一輪的改動必須先 push ⇒
  順序變成「測項全綠 → push → 線上驗 → 必要時當輪修正」，而不是「commit 前就目視過」。
  對**數學/結算**類改動這不夠謹慎（應維持 node 證明為主）；對**演出/時序**類改動則是目前唯一可行且真實的路徑。
- **本輪未查證這條路在別台機器/別的排程環境是否同樣可用**。若某輪 `preview_start {url}` 也被拒，
